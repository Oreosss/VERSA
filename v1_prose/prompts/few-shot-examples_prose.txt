Impact: Confidentiality HIGH | Integrity HIGH | Availability HIGH

What is vulnerable
Tongda OA, an office automation platform, contains a SQL injection flaw in versions 2017 through 11.9. The problem is in the $AFF_ID parameter of the /affair/delete.php page, where user-supplied input reaches a database query without proper handling. SQL injection means an attacker can smuggle database commands in through a normal input field, and those commands are then run by the database, which can let the attacker read, change, or delete stored data such as user records.

How it can be exploited
Because the attack vector is NETWORK with no privileges and no user interaction required, an attacker can reach this remotely over the network without logging in and without needing anyone to click anything. The source does not describe a specific exploit sequence, so the practical impact stated here follows from the CVSS fields rather than a demonstrated attack. The HIGH ratings across confidentiality, integrity, and availability indicate the database could be read, altered, or made unavailable.

What action to take
Confirm whether any Tongda OA instance in the affected version range is in use. No official vendor fix is listed on NVD for this vulnerability, so check directly with Tongda for a patch and treat the linked third-party writeup as background rather than a confirmed remedy.
Reference
A third-party reference documenting the vulnerability: https://github.com/cqliuke/cve/blob/main/sql.md

CVE-2020-15078 | CVSS 7.5 HIGH
Attack vector: NETWORK | Privileges required: NONE | User interaction: NONE
Impact: Confidentiality HIGH | Integrity NONE | Availability NONE
KEV listed: NO | EPSS: 5.1% (91st percentile)

What is vulnerable
OpenVPN, a widely used VPN server and client, has a vulnerability in version 2.5.1 and earlier that lets an attacker get past the login step and connect to the VPN server without valid credentials. It only affects servers set up with deferred authentication, which is an option where the server waits for a separate system to approve each login before letting the user in. On those servers, an attacker who has not been authenticated can reach the connection's control channel, the internal traffic OpenVPN uses to set up and manage a session.

How it can be exploited
Because the attack vector is NETWORK with no privileges and no user interaction required, an attacker can attempt this remotely without valid credentials and without needing anyone to act. The source states the bypass can potentially be used to trigger further information leaks. The impact fields support this reading, with confidentiality rated HIGH but integrity and availability rated NONE, meaning the flaw exposes information rather than letting an attacker alter data or take the service down.

What action to take
Confirm whether any OpenVPN server at version 2.5.1 or earlier is running with deferred authentication, since the flaw applies to that configuration. The vendor's advisories explain the underlying cause and carry the fix, so consult them and the distribution advisories in the references for upgrade guidance.

CVE-2026-5867 | CVSS 4.3 MEDIUM
Attack vector: NETWORK | Privileges required: NONE | User interaction: REQUIRED
Impact: Confidentiality LOW | Integrity NONE | Availability NONE
KEV listed: NO | EPSS: 0.24% (15th percentile)

What is vulnerable
Google Chrome has a vulnerability in versions before 147.0.7727.55, in a browser component called WebML. It is a heap buffer overflow, a type of memory error where a program writes or reads outside the block of memory it was meant to use, which can let it access nearby data that should not be exposed. Here the effect is that an attacker can obtain potentially sensitive information from the browser's process memory, meaning data the browser is holding in memory while it runs.

How it can be exploited
The attack works through a crafted HTML page, so the user has to be led to open a malicious web page for the attack to trigger, which is why the user interaction field is REQUIRED. Once the page is opened, the flaw can leak fragments of the browser's memory to the attacker. The impact fields keep this in proportion, with confidentiality rated LOW and integrity and availability rated NONE, so this exposes limited information rather than letting an attacker change data or crash the browser. Google records this internally as a high-severity issue while the CVSS score places it at MEDIUM, so both a vendor concern and a moderate formal rating apply.

What action to take
Update Chrome to version 147.0.7727.55 or later, which is the release that addresses this. Chrome usually updates itself, so confirm the browser is on the current stable version rather than assuming it has already applied it.

CVE-2020-10901 | CVSS 3.3 LOW
Attack vector: LOCAL | Privileges required: NONE | User interaction: REQUIRED
Impact: Confidentiality LOW | Integrity NONE | Availability NONE
KEV listed: NO | EPSS: 3.4% (87th percentile)

What is vulnerable
Foxit PhantomPDF, a PDF reader and editor, has a vulnerability in version 9.7.1.29511. The flaw is in the way the software handles U3D objects, which are 3D models that can be embedded inside a PDF file. When PhantomPDF processes one of these objects it does not properly check the data it is given, which can cause it to read past the end of an allocated block of memory. This means it reads data outside the area it was meant to, exposing information that should not be accessible.

How it can be exploited
Exploiting this needs the victim to open a malicious PDF file or visit a page carrying one, which is why the user interaction field is REQUIRED. On its own the flaw exposes a limited amount of information, which matches the LOW confidentiality impact and the NONE ratings for integrity and availability. The description notes that an attacker could combine it with other separate vulnerabilities to run code on the affected machine, so the more serious outcome depends on chaining this with other flaws rather than following from this one alone.

What action to take
Update Foxit PhantomPDF to a version later than 9.7.1.29511, since that release and earlier are affected. The vendor and the linked advisory carry the fix and further detail, so use the current version from Foxit rather than assuming an installed copy is already patched.
