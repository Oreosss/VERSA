Summarise the following vulnerability for a reader who does not work in
security.

Write a summary of the target CVE in exactly three parts, under these headings:

What is vulnerable
How it can be exploited
What action to take

Follow these instructions:

- Use only the information provided. Do not introduce details not present in
  the source. If something is not stated, say so rather than inferring it.

- Use the attack vector, privileges required, and user interaction fields to
  explain the practical conditions under which this can be exploited.

- The KEV and EPSS values are provided for the reader's context only. Do not
  describe or interpret them in the summary.

- The additional CVEs are related vulnerabilities provided as reference context
  only. Do not summarise them. The summary is about the target CVE only.

- Explain the risk plainly. Do not use fear-based or urgency-inflating language.
  Do not exaggerate severity beyond what the CVSS score and fields support.

- You are writing for a technically capable colleague who does not work in
  security. Assume general software and systems knowledge, not security
  terminology. Define terms inline.

- In the "What action to take" section, point to the referenced sources for
  remediation rather than inventing a fix. Where no fix is present in the
  source, state that plainly and direct the reader to the vendor.

- After the three parts, add a "Reference" section listing the source links
  provided, each labelled by what the source is.

Here are worked examples of the format and register expected.

=== EXAMPLE 1 ===

INPUT:
CVE-2024-25320 | CVSS 9.8 CRITICAL
Attack vector: NETWORK | Privileges required: NONE | User interaction: NONE
Impact: Confidentiality HIGH | Integrity HIGH | Availability HIGH
KEV listed: NO | EPSS: 0.73% (approx median)
Description: Tongda OA v2017 and up to v11.9 was discovered to contain a SQL
injection vulnerability via the $AFF_ID parameter at /affair/delete.php.
Reference: https://github.com/cqliuke/cve/blob/main/sql.md

OUTPUT:
What is vulnerable
Tongda OA, an office automation platform, contains a SQL injection flaw in
versions 2017 through 11.9. The problem is in the $AFF_ID parameter of the
/affair/delete.php page, where user-supplied input reaches a database query
without proper handling. SQL injection means an attacker can smuggle database
commands in through a normal input field, and those commands are then run by
the database, which can let the attacker read, change, or delete stored data
such as user records.

How it can be exploited
Because the attack vector is NETWORK with no privileges and no user interaction
required, an attacker can reach this remotely over the network without logging
in and without needing anyone to click anything. The HIGH ratings across
confidentiality, integrity, and availability indicate the database could be
read, altered, or made unavailable.

What action to take
Confirm whether any Tongda OA instance in the affected version range is in use.
No official vendor fix is listed on NVD for this vulnerability, so check
directly with Tongda for a patch and treat the linked third-party writeup as
background rather than a confirmed remedy.

Reference
A third-party reference documenting the vulnerability:
https://github.com/cqliuke/cve/blob/main/sql.md

INPUT:
CVE-2020-15078 | CVSS 7.5 HIGH
Attack vector: NETWORK | Privileges required: NONE | User interaction: NONE
Impact: Confidentiality HIGH | Integrity NONE | Availability NONE
KEV listed: NO | EPSS: 5.1% (91st percentile)
Description: OpenVPN 2.5.1 and earlier versions allows a remote attackers to
bypass authentication and access control channel data on servers configured
with deferred authentication, which can be used to potentially trigger further
information leaks.
Reference: https://community.openvpn.net/openvpn/wiki/CVE-2020-15078 (OpenVPN, vendor)
Reference: https://security.gentoo.org/glsa/202105-25 (Gentoo)
Reference: https://usn.ubuntu.com/usn/usn-4933-1 (Ubuntu)

OUTPUT:
What is vulnerable
OpenVPN, a widely used VPN server and client, has a vulnerability in version
2.5.1 and earlier that lets an attacker get past the login step and connect to
the VPN server without valid credentials. It only affects servers set up with
deferred authentication, which is an option where the server waits for a
separate system to approve each login before letting the user in. On those
servers, an attacker who has not been authenticated can reach the connection's
control channel, the internal traffic OpenVPN uses to set up and manage a
session.

How it can be exploited
Because the attack vector is NETWORK with no privileges and no user interaction
required, an attacker can attempt this remotely without valid credentials and
without needing anyone to act. The bypass can potentially be used to trigger
further information leaks. The impact fields support this reading, with
confidentiality rated HIGH but integrity and availability rated NONE, meaning
the flaw exposes information rather than letting an attacker alter data or take
the service down.

What action to take
Confirm whether any OpenVPN server at version 2.5.1 or earlier is running with
deferred authentication, since the flaw applies to that configuration. The
vendor's advisories explain the underlying cause and carry the fix, so consult
them and the distribution advisories in the references for upgrade guidance.

Reference
Advisories documenting the vulnerability:
OpenVPN, the affected software vendor: https://community.openvpn.net/openvpn/wiki/CVE-2020-15078
Gentoo: https://security.gentoo.org/glsa/202105-25
Ubuntu: https://usn.ubuntu.com/usn/usn-4933-1

=== EXAMPLE 3 ===

INPUT:
CVE-2026-5867 | CVSS 4.3 MEDIUM
Attack vector: NETWORK | Privileges required: NONE | User interaction: REQUIRED
Impact: Confidentiality LOW | Integrity NONE | Availability NONE
KEV listed: NO | EPSS: 0.24% (15th percentile)
Description: Heap buffer overflow in WebML in Google Chrome prior to
147.0.7727.55 allowed a remote attacker to obtain potentially sensitive
information from process memory via a crafted HTML page. (Chromium security
severity: High)
Reference: https://chromereleases.googleblog.com/2026/04/stable-channel-update-for-desktop.html (Google Chrome, vendor)
Reference: https://issues.chromium.org/issues/492668885 (Chromium issue tracker)

OUTPUT:
What is vulnerable
Google Chrome has a vulnerability in versions before 147.0.7727.55, in a browser
component called WebML. It is a heap buffer overflow, a type of memory error
where a program writes or reads outside the block of memory it was meant to use,
which can let it access nearby data that should not be exposed. Here the effect
is that an attacker can obtain potentially sensitive information from the
browser's process memory, meaning data the browser is holding in memory while it
runs.

How it can be exploited
The attack works through a crafted HTML page, so the user has to be led to open a
malicious web page for the attack to trigger, which is why the user interaction
field is REQUIRED. Once the page is opened, the flaw can leak fragments of the
browser's memory to the attacker. The impact fields keep this in proportion,
with confidentiality rated LOW and integrity and availability rated NONE, so
this exposes limited information rather than letting an attacker change data or
crash the browser. Google records this internally as a high-severity issue while
the CVSS score places it at MEDIUM, so both a vendor concern and a moderate
formal rating apply.

What action to take
Update Chrome to version 147.0.7727.55 or later, which is the release that
addresses this. Chrome usually updates itself, so confirm the browser is on the
current stable version rather than assuming it has already applied it.

Reference
Advisories documenting the vulnerability:
Google Chrome, the affected software vendor: https://chromereleases.googleblog.com/2026/04/stable-channel-update-for-desktop.html
Chromium issue tracker: https://issues.chromium.org/issues/492668885

=== EXAMPLE 4 ===

INPUT:
CVE-2020-10901 | CVSS 3.3 LOW
Attack vector: LOCAL | Privileges required: NONE | User interaction: REQUIRED
Impact: Confidentiality LOW | Integrity NONE | Availability NONE
KEV listed: NO | EPSS: 3.4% (87th percentile)
Description: This vulnerability allows remote attackers to disclose sensitive
information on affected installations of Foxit PhantomPDF 9.7.1.29511. User
interaction is required to exploit this vulnerability in that the target must
visit a malicious page or open a malicious file. The specific flaw exists within
the handling of U3D objects in PDF files. The issue results from the lack of
proper validation of user-supplied data, which can result in a read past the end
of an allocated object. An attacker can leverage this in conjunction with other
vulnerabilities to execute code in the context of the current process. Was
ZDI-CAN-10461.
Reference: https://www.foxitsoftware.com/support/security-bulletins.php (Foxit, vendor)
Reference: https://www.zerodayinitiative.com/advisories/ZDI-20-529/ (Zero Day Initiative, researcher)

OUTPUT:
What is vulnerable
Foxit PhantomPDF, a PDF reader and editor, has a vulnerability in version
9.7.1.29511. The flaw is in the way the software handles U3D objects, which are
3D models that can be embedded inside a PDF file. When PhantomPDF processes one
of these objects it does not properly check the data it is given, which can
cause it to read past the end of an allocated block of memory. This means it
reads data outside the area it was meant to, exposing information that should
not be accessible.

How it can be exploited
Exploiting this needs the victim to open a malicious PDF file or visit a page
carrying one, which is why the user interaction field is REQUIRED. On its own
the flaw exposes a limited amount of information, which matches the LOW
confidentiality impact and the NONE ratings for integrity and availability. The
description notes that an attacker could combine it with other separate
vulnerabilities to run code on the affected machine, so the more serious outcome
depends on chaining this with other flaws rather than following from this one
alone.

What action to take
Update Foxit PhantomPDF to a version later than 9.7.1.29511, since that release
and earlier are affected. The vendor and the linked advisory carry the fix and
further detail, so use the current version from Foxit rather than assuming an
installed copy is already patched.

Reference
Advisories documenting the vulnerability:
Foxit, the affected software vendor: https://www.foxitsoftware.com/support/security-bulletins.php
Zero Day Initiative, the disclosing researcher: https://www.zerodayinitiative.com/advisories/ZDI-20-529/
