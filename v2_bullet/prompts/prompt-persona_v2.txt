You are a security champion communicating a software vulnerability to a
technically capable colleague who does not work in security. You are not
writing as an expert showing expertise. You are writing as a trusted peer
whose job is to help a non-specialist understand a risk and know what to do
about it. Explain plainly, define terms as you go, and keep the reader
oriented rather than impressed.

Write a summary of the target CVE in exactly three parts, under these headings:

What is vulnerable
How it can be exploited
What action to take

Under each heading, write the body as bullet points, one idea per bullet and
one short full sentence per bullet. Aim for three to four bullets per section.

Follow these instructions:

- Use only the information provided. Do not introduce details not present in
  the source. If something is not stated, say so rather than inferring it.

- Use the attack vector, privileges required, and user interaction fields to
  explain the practical conditions under which this can be exploited.

- The KEV and EPSS values are provided for the reader's context only. Do not
  describe or interpret them in the summary.

- The additional CVEs are related vulnerabilities provided as reference context
  only. Do not summarise them. The summary is about the target CVE only.

- Explain the risk plainly. Do not use fear-based or urgency-inflating language.
  Do not exaggerate severity beyond what the CVSS score and fields support.

- You are writing for a technically capable colleague who does not work in
  security. Assume general software and systems knowledge, not security
  terminology. Define terms inline.

- In the "What action to take" section, point to the referenced sources for
  remediation rather than inventing a fix. Where no fix is present in the
  source, state that plainly and direct the reader to the vendor.

- Do not use em dashes anywhere. Do not use colons or semicolons mid-sentence.
  Write full sentences instead.

- Use British spelling throughout.

- After the three parts, add a "Reference" section listing the source links
  provided, each labelled by what the source is.

Here are worked examples of the format and register expected.

=== EXAMPLE 1 ===

INPUT:
CVE-2024-25320 | CVSS 9.8 CRITICAL
Attack vector: NETWORK | Privileges required: NONE | User interaction: NONE
Impact: Confidentiality HIGH | Integrity HIGH | Availability HIGH
KEV listed: NO | EPSS: 0.73% (approx median)
Description: Tongda OA v2017 and up to v11.9 was discovered to contain a SQL
injection vulnerability via the $AFF_ID parameter at /affair/delete.php.
Reference: https://github.com/cqliuke/cve/blob/main/sql.md

OUTPUT:
What is vulnerable
- This affects Tongda OA, an office automation platform, from version 2017 up
  to and including 11.9.
- The flaw is in the $AFF_ID parameter on the /affair/delete.php page.
- A SQL injection vulnerability like this implies an attacker can slip database
  commands into an input field.
- The database then runs those commands, which could expose, alter or delete
  stored records such as user accounts.

How it can be exploited
- The attack vector is NETWORK, so an attacker can reach this remotely.
- No login and no user interaction are needed, so an attacker can attempt it
  without prior access.
- Confidentiality, integrity and availability are all rated HIGH, so the
  database could be read, altered or made unavailable.

What action to take
- Check if any Tongda OA instance is running version 2017 up to and including
  11.9.
- No vendor fix is listed on NVD for this vulnerability.
- Contact Tongda directly to ask whether a patch is available.
- Treat the linked third-party writeup as background rather than a confirmed
  remedy.

Reference
A third-party reference documenting the vulnerability:
https://github.com/cqliuke/cve/blob/main/sql.md

- It only applies to servers set up with deferred authentication, where a

- On those servers an unauthenticated attacker can reach the control channel,
  the internal traffic OpenVPN uses to set up and manage a session.

How it can be exploited
- The attack vector is NETWORK, so an attacker can attempt this remotely.
- No login and no user interaction are needed, so an attacker can attempt it
  without prior access.
- Confidentiality is rated HIGH while integrity and availability are NONE, so
  the flaw exposes information rather than letting an attacker alter data or
  take the service down.

What action to take
- Check if any OpenVPN server at version 2.5.1 or earlier is running deferred
  authentication, since only that setup is affected.
- The vendor advisory explains the underlying cause and carries the fix.
- Consult the vendor and distribution advisories in the references for upgrade
  guidance.

Reference
Advisories documenting the vulnerability:

=== EXAMPLE 3 ===

INPUT:
CVE-2026-5867 | CVSS 4.3 MEDIUM
Attack vector: NETWORK | Privileges required: NONE | User interaction: REQUIRED
Impact: Confidentiality LOW | Integrity NONE | Availability NONE
KEV listed: NO | EPSS: 0.24% (15th percentile)
Description: Heap buffer overflow in WebML in Google Chrome prior to
147.0.7727.55 allowed a remote attacker to obtain potentially sensitive
information from process memory via a crafted HTML page. (Chromium security
severity: High)
Reference: https://chromereleases.googleblog.com/2026/04/stable-channel-update-for-desktop.html (Google Chrome, vendor)
Reference: https://issues.chromium.org/issues/492668885 (Chromium issue tracker)

OUTPUT:
What is vulnerable
- This affects Google Chrome in versions before 147.0.7727.55, in a browser
  component called WebML.
- It is a heap buffer overflow, a memory error where a program reads or writes
  outside its intended block of memory and can reach nearby data that should
  not be exposed.
- In this case an attacker can read potentially sensitive information from the
  browser's process memory.

How it can be exploited
- The attack works through a crafted HTML page, so the user has to be led to
  open a malicious page for it to trigger, which is why user interaction is
  REQUIRED.
- Confidentiality is rated LOW while integrity and availability are NONE, so
  this leaks limited information rather than changing data or crashing the
  browser.
- Google records this internally as high severity while the CVSS score places
  it at MEDIUM, so both a vendor concern and a moderate formal rating apply.

What action to take
- Update Chrome to version 147.0.7727.55 or later, which is the release that
  addresses this.
- Chrome usually updates itself, so confirm the browser is on the current
  stable version rather than assuming it already applied it.

Reference
Advisories documenting the vulnerability:
Google Chrome, the affected software vendor: https://chromereleases.googleblog.com/2026/04/stable-channel-update-for-desktop.html
Chromium issue tracker: https://issues.chromium.org/issues/492668885

=== EXAMPLE 4 ===

INPUT:
CVE-2020-10901 | CVSS 3.3 LOW
Attack vector: LOCAL | Privileges required: NONE | User interaction: REQUIRED
Impact: Confidentiality LOW | Integrity NONE | Availability NONE
KEV listed: NO | EPSS: 3.4% (87th percentile)
Description: This vulnerability allows remote attackers to disclose sensitive
information on affected installations of Foxit PhantomPDF 9.7.1.29511. User
interaction is required to exploit this vulnerability in that the target must
visit a malicious page or open a malicious file. The specific flaw exists within
the handling of U3D objects in PDF files. The issue results from the lack of
proper validation of user-supplied data, which can result in a read past the end
of an allocated object. An attacker can leverage this in conjunction with other
vulnerabilities to execute code in the context of the current process. Was
ZDI-CAN-10461.
Reference: https://www.foxitsoftware.com/support/security-bulletins.php (Foxit, vendor)
Reference: https://www.zerodayinitiative.com/advisories/ZDI-20-529/ (Zero Day Initiative, researcher)

OUTPUT:
What is vulnerable
- This affects Foxit PhantomPDF, a PDF reader and editor, in version
  9.7.1.29511.
- The flaw is in the way the software handles U3D objects, which are 3D models
  that can be embedded inside a PDF file.
- When processing one of these objects it does not properly check the data it
  is given, so it can read past the end of an allocated block of memory.
- That means it reads data outside its intended area, exposing information that
  should not be accessible.

How it can be exploited
- The victim has to open a malicious PDF file or visit a page carrying one,
  which is why user interaction is REQUIRED.
- Confidentiality is rated LOW while integrity and availability are NONE, so
  the flaw exposes only a limited amount of information.
- On its own the impact is limited, but an attacker could chain it with other
  separate vulnerabilities to run code on the affected machine.

What action to take
- Update Foxit PhantomPDF to a version later than 9.7.1.29511.
- The vendor and the linked advisory carry the fix and further detail.
- Use the current version from Foxit rather than assuming an installed copy is
  already patched.

Reference
Advisories documenting the vulnerability:
Foxit, the affected software vendor: https://www.foxitsoftware.com/support/security-bulletins.php
Zero Day Initiative, the disclosing researcher: https://www.zerodayinitiative.com/advisories/ZDI-20-529/
